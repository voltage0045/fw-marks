# 废文网 · 书签标记 & 云同步

iOS Safari 用户脚本。不需要 Xcode，不需要签名，不会过期。

## 文件

| 文件 | 用途 |
|---|---|
| `fw-marks.user.js` | **正式脚本，装这个** |
| `fw-probe.user.js` | 备用调试工具。只有在自动识别失灵、且校准也修不好时才用 |
| `test/run-test.py` | Mac 本地测试台，装手机前先跑它 |
| `test/pages/` | 测试夹具：14 个真实页面的 DOM 骨架（正文已替换成占位符） |

## 零、先在 Mac 上测一遍（推荐，1 分钟）

### 方式 A：自动测试台（不用连网、不碰真站）

```bash
cd fw-marks
python3 test/run-test.py
```

它会起一个本地服务，把 `test/pages/` 里那 14 个真实页面**按 URL 模式**伺服
（所以随便点 id 都能开，不会到处 404），注入脚本 + 一份假数据，
再用 headless Chrome 逐页跑、逐条断言。全绿就是没问题：

```
=== 书籍介绍 + 目录页 ===        === 正文页（一页多章）===
  ✅ 目录角标画出来了              ✅ 6 章都挂上了标记条
  ✅ 书名后挂了书籍标签            ✅ 每章都有 🔖 按钮
  ✅ 书名后显示书签数 🔖2          ✅ 点 🔖 真能加上书签
  ✅ 有「上次读到」提示条          ✅ 同位置再点 = 取消

=== 单章固定链接页 ===           === 收藏 / 首页 / 频道 / 索引 ===
  ✅ 只认出 1 章（回帖没被算进来） ✅ 书名后挂上了标签
64/64 通过
```

覆盖的页面：首页、收藏、文库、书籍介绍、纯目录列表、正文、单章固定链接、
主题索引、频道、动态、个人中心、标签云、某标签下的书。

它不只看「画对了没」，还会真的 `click()` 一下再读存储 —— 画得对但点不动照样会红。
另外专门盯着几个回归点：

- 点「上次读到」必须跳**章节固定链接**并自动复位，不能原地刷新
- 单章页只能认出 1 章（同页那 4 条回帖不许被当成章节）
- v1.0 留下的假数据（书 ID 被当成章 ID）必须被清掉，且不许误删真书

想自己用眼睛看：`python3 test/run-test.py --serve`，浏览器开 <http://127.0.0.1:8899/>，
可点的地址都列在 <http://127.0.0.1:8899/__routes__>。
碰到没抓夹具的页面会给张说明页（不是 404），照着往 `PATTERNS` 加一行就行。

> 夹具的样式表指向站点 CDN，本地没代理会加载不出来 —— 页面很朴素，但功能照跑。

两个踩过的坑，改脚本时别踩回去：

- Chrome 必须用 **`--headless=old`**。新版 `--headless=new` 是个真 app 进程，
  会在 Dock 里注册图标一直跳；旧版是纯后台进程，抓 DOM 能力完全一样
- 每次启 Chrome 都要**独立的 `--user-data-dir`**。共用一个的话，上一个还没退干净时
  新启的会挂到那个实例上开标签页，`--dump-dom` 一个字都不输出 ——
  表现就是「单独跑能过、连着跑就挂」

### 方式 B：在真站上试，零安装

Safari → 设置 → 高级 → 勾「显示网页开发者功能」→ 打开废文网任意页面 →
**开发 → 显示 JavaScript 控制台** → 把 `fw-marks.user.js` 全文粘进去回车。
网站顶栏立刻多出一项 **📑 我的标记**。

脚本检测不到扩展的 GM API 时会自动降级用 `localStorage`，所以裸控制台里也能跑完整功能
（只有跨域的坚果云同步会被浏览器 CORS 拦住，GitHub Gist 不受影响）。
缺点是刷新就没了，适合快速验证。

### 方式 C：Mac 版 Userscripts（和 iPhone 完全一致的环境）

Mac App Store 搜 **Userscripts** —— 和 iOS 是同一个 App，GM 存储、跨域行为都一样。
装好后把脚本放进它的目录，Safari 里启用即可。

> **省事技巧**：Mac 和 iPhone 的 Userscripts 都把目录指到 iCloud Drive 里同一个文件夹。
> 这样 Mac 上改完存盘，iPhone 刷新页面就生效，再也不用来回传文件。

## 一·五、更新脚本

脚本头里已经配好了远程更新地址：

```
@version      当前版本号
@updateURL    https://raw.githubusercontent.com/voltage0045/fw-marks/main/fw-marks.meta.js
@downloadURL  https://raw.githubusercontent.com/voltage0045/fw-marks/main/fw-marks.user.js
```

**但别指望它后台自己更新** —— Userscripts 有个 release 说明提到
**自动更新检查曾被暂时禁用**，实测（v4.8.6）放了远端新版本也不会自己拉。
所以要么从扩展弹窗里手动触发检查，要么走下面的兜底办法。

发新版时两个文件**必须一起传**（`.meta.js` 是给扩展比版本号用的，
只传 `.user.js` 它不知道有新版）：

```bash
cd ~/fw-marks
# 改完代码后：升 @version → 重新生成 meta → 提交推送
python3 -c "import re;s=open('fw-marks.user.js',encoding='utf-8').read();\
open('fw-marks.meta.js','w',encoding='utf-8').write(\
re.search(r'// ==UserScript==.*?// ==/UserScript==',s,re.S).group(0)+'\n')"
git add -A && git commit -m "vX.Y.Z" && git push
```

### 兜底：直接覆盖文件（最可靠）

**Mac**：
```bash
cp ~/fw-marks/fw-marks.user.js \
  ~/Library/Containers/com.userscripts.macos.Userscripts-Extension/Data/Documents/scripts/
```

**iPhone**：起个局域网取件服务，手机 Safari 下载后移到 Userscripts 目录。
（公司 Wi-Fi 常开客户端隔离 → 用 iPhone 开热点、Mac 连上去，就绕过了）

### 怎么看装的是哪个版本

```bash
grep -m1 "@version" \
  ~/Library/Containers/com.userscripts.macos.Userscripts-Extension/Data/Documents/scripts/fw-marks.user.js
```
或者：Safari 点 Userscripts 扩展图标 → 点那条脚本 → 编辑器里第 4 行。

> 外部编辑器改完脚本后，**必须先点开扩展弹窗并等它加载完**，注入才会生效 ——
> 这是 Userscripts 的已知行为。

## 二、配置云同步（双备份）

顶栏 **📑 我的标记** → `⚙️ 同步设置`。两个都填上才是双备份，只填一个也能用。

### ① GitHub 私有仓库

**手机上不需要 git**，脚本直接调 GitHub 的 HTTP API（`api.github.com`），
不用客户端、不用命令行、一次 commit 都不用手动做。

1. 浏览器打开 github.com → **New repository** → 勾 **Private** → 建好（不用 git）
2. GitHub → Settings → Developer settings → **Fine-grained tokens** → Generate new token
   - Repository access：**Only select repositories** → 选刚建的那个私有仓库
   - Permissions → Repository permissions → **Contents: Read and write**（只给这一个）
3. 生成的 `github_pat_...` 填进「Token」栏
4. 「仓库」栏填 `owner/仓库名`；路径默认 `fw-marks.json`（文件不存在会自动创建）；分支留空＝默认分支

> 为什么不用 gist：gist 的 `public:false` 只是「不被列出、搜不到」，**拿到链接谁都能看**，
> 不是鉴权存储。私有仓库是真鉴权的。
>
> 顺带：细粒度 PAT 只授权**一个**仓库的 Contents，比 classic token 的 `gist` scope
> （能读写你名下**所有** gist）爆炸半径小得多。

### ② 坚果云 WebDAV

1. 坚果云网页版 → 右上角头像 → 账户信息 → **安全选项**
2. 「第三方应用管理」→ 添加应用 → 名字随便填 → **生成密码**
3. 填进设置页：
   - 账号 = 坚果云注册邮箱
   - 应用密码 = 刚生成的那串（**不是登录密码**）
   - 地址保持默认 `https://dav.jianguoyun.com/dav/fw-marks.json` 即可

填完点「保存设置」→「立即同步」。两行都显示 ✅ 就成了。

### 同步逻辑

每次同步：**两边都拉下来 → 和本地逐条比 `updatedAt` 取最新 → 合并结果推回两边**。

- 手机标了 A 章、iPad 标了 B 章 → 合并后两边都在，不会互相覆盖
- 哪个云端落后 → 推送时自动补齐
- 一个云端挂了 → 另一个照常工作，设置页会显示 ⚠️ 和失败原因
- 删除是软删除（打 `deleted` 标记），所以删掉的不会被同步「复活」
- **Token 和密码只存本机，永远不会上传到任何云端**

默认打开网页时会静默同步一次（距上次超过 5 分钟才触发），失败不弹窗打扰。

## 三、用法

> 核心原则：**常用的操作都直接摆在网页上**。
> **没有悬浮球** —— 那玩意儿会实打实压住网站自己的按钮（正好压在上面就点不到了），
> 每页还糊一个球在眼前。需要打字（备注、总评）和查列表时才进面板，入口有两个：
>
> - 网站**顶栏**多出一项 **📑 我的标记** —— 全站都能进
> - **书籍页目录上方**一排按钮 —— 就近操作

### 书签 vs 阅读进度 —— 两码事

| | 阅读进度 | 书签 |
|---|---|---|
| 怎么来的 | **自动**记，滚动时持续更新 | **手动**加，点 🔖 |
| 一本书能有几个 | 只有 1 个 | 想加几个加几个 |
| 会不会被覆盖 | **会**，一直被最新位置顶掉 | **不会**，只有你自己能删 |
| 要起名字吗 | 不用 | **不用** —— 章节名 + 百分比 + 那句原文就够认了 |

所以：想「下次接着读」靠进度就行；想「这段以后要回来看」就加书签。

**加书签**：正文页每章标题下面那条标记条上点 `🔖`。
- 点的是**你正在读的那一章** → 记的是**当前屏幕位置**
- 点的是**别的章** → 记的是那一章的**开头**
- **同一个位置再点一次 = 取消**（±5% 以内算同一个位置，手抖连点不会攒出一堆重复的）
- 面板里也有「🔖 在我现在读到的位置加书签」

**看/跳书签**：
- 章节的 🔖 按钮上直接显示这一章有几个书签
- 目录页章节后面挂 🔖，书名后面和书列表里挂 `🔖n`
- 书籍页点「📖 标签 / 总评 / 书签」能看这本书的全部书签，点一条就跳过去
- 顶栏「📑 我的标记」里每本书有个「🔖 书签 n」按钮可展开
- 书签会连同章节名、位置原文一起进搜索

跳转用的是章节固定链接 `/posts/{id}`，**不是 `?page=N`** —— 作者一更新页码就漂了，
固定链接才稳。跳过去之后自动复位到书签那个位置。

### 正文页（`/threads/{书}`，一页好几章）
- **每章标题下面直接一条标记条**：`精彩` `一般` `跳过` 三个钮，点一下就标，再点取消，
  不用进面板。旁边 `📝` 是写备注（这个才会弹面板），`🔖` 是加书签
- 读到的那一章标记条上显示 **▶ 读到这里**
- 面板永远对着**你当前视口里那一章**，滚动时自动跟着换
- 滚动时自动记录进度。下次回到这一页会问「上次读到「章名」xx%，回去吗？」
  定位优先用**视口顶部那句话**的文本锚点，换字号、换设备都能精准找回；
  锚点对不上时退回「那一章 + 章内百分比」

> 同一页里混着的回帖不会被当成章节 —— 回帖没有标题行，脚本据此剔掉。

### 书籍介绍 / 目录页（`/threads/{书}/profile` 和 `/threads/{书}/chapter_index`）

> 目录有**两个入口**：书籍介绍页里嵌的那份，和「目录列表」独立页。两者结构一样，都认。
- **书名后面直接挂这本书的标签**（蓝色）、▶ 读到哪章、标了几章、有总评则 📝
- **目录上方压一条**「▶ 上次读到「章名」xx% —— 点这里继续」，点了直接跳回去
- 每个章节标题后面挂上你打的标签色块，有备注的显示 📝，读到的那章前面有 ▶
  （手机版目录和桌面版表格都画，显示哪个由网站自己的响应式决定）
- 目录上方那排按钮点「📖 标签 / 总评 / 书签」，可以写**整本书的总评**、打**自定义标签**
  （点「＋ 新标签」新建，用过的会进标签池，以后直接点选）

### 书列表 / 搜索结果（`/books`、`/thread_index`、标签页…）
每本书的书名后面直接挂标签 + ▶ 读到哪章 + 标了几章。扫一眼就知道哪本在追、哪本弃了。

### 全部书签
顶栏 **📑 我的标记**。所有书的列表，可搜书名 / 标签 / 章节名 / 备注 / 书签。
每本书能展开看标记过的章节、一键跳转、删除。底下有「复制导出 JSON」和「粘贴导入」做本地兜底备份。

## 四、出问题了

| 症状 | 办法 |
|---|---|
| 目录页角标位置不对 / 没出现 | 顶栏「📑 我的标记」→ `⚙️ 同步设置` → **重新校准** → 点一下任意章节链接 |
| 面板说「没认出这一页」 | 同上，去目录页校准一次 |
| 顶栏那一项不出现 | 检查扩展是否对本站「始终允许」；点一次扩展图标让弹窗加载完 |
| 坚果云报 401 | 用的是登录密码而不是**应用密码** |
| 坚果云报 409 | 地址里的上级文件夹在坚果云里不存在，先建好 |
| GitHub 报 401 / 403 | Token 过期，或没给那个仓库的 **Contents: Read and write** |
| GitHub 报 404 | `owner/仓库名` 写错了，或 token 没授权到这个仓库 |
| 网站换了域名 | 编辑脚本顶部，照着改 `@match` 那一行 |
| 点「上次读到」只是刷新了页面 | v1.0 的老毛病，v1.2.1 已修。首次打开会自动清掉那条假记录并提示，重新读一次就会记对 |

**改脚本 = 直接编辑那个 `.js` 文件，刷新网页就生效**，不用重装、不用重签喵。

### 一次性数据修复（v1.0 → v1.2.1）

v1.0 靠启发式猜 URL 规律，在这个站上猜错了：**书籍介绍页被当成正文页**，
于是「书 ID」和「章 ID」被解析成了同一个数字。后果就是
`progress.cid == 书 ID` → 点「继续读」跳回书籍主页自己 = 原地刷新。

v1.2.1 首次运行会自动认出这类记录（章 ID 不可能等于书 ID）并软删掉，
顺手把纯空壳的假书条目也清掉 —— 但**有标记、有书签、有标签或有总评的真书一律不动**。
清理会同步到云端，所以另一台设备上也不会再冒出来。

## 五、数据存在哪

- 本地：Safari 扩展存储（不是网站的 localStorage，Safari 的隐私清理不会碰它）
- 云端：GitHub **私有仓库** + 坚果云 WebDAV，**两边都是账号鉴权**，各一份完整 JSON
- 手动：设置页可随时复制导出 JSON

数据结构（同步的就是这几坨）：

| | 内容 |
|---|---|
| `books[书id]` | 书名、自定义标签、总评、阅读进度 |
| `chaps[书id\|章id]` | 章节评价（精彩/一般/跳过）、备注 |
| `bmks[书id\|章id-时间戳]` | 书签：位置、章节名、定位锚文本 |
| `tagPool` | 用过的自定义标签，下次直接点选 |

> 注意这里面有进度/书签的**约 40 字定位锚文本**（会暴露你读了什么），
> 所以两个云端都选了鉴权存储，别放公共仓库。

删除一律**软删**（打 `deleted` 标记 + 时间戳），否则同步会把删掉的东西复活。

### 账号凭据说明

**脚本里没有任何账号信息**，一行都没有。搜 `token` / `davUser` 你会看到它们的初始值全是空字符串。

- 云同步**完全可选**。不填任何东西，脚本就是个纯本地工具，不联网、不发请求
- 想同步的话，凭据是**你自己在「⚙️ 同步设置」里粘贴进去的**，不会跳转登录、
  不会走 OAuth、也不会有人代你登录
- 建议用的都是**受限凭据**，不是你的登录密码：
  - GitHub：**细粒度** PAT，只授权**那一个私有仓库**的 Contents 读写，碰不到你其他仓库
  - 坚果云：**应用密码**（第三方应用管理里单独生成的），可以随时单独吊销
- 凭据存在扩展本地存储里，**只在向 `api.github.com` / `dav.jianguoyun.com`
  发同步请求时用作认证头**。它们不会被写进同步的 JSON，所以云端那份备份里也没有凭据
- 想确认的话：`test/run-test.py` 里的种子数据就是空凭据，
  或者直接 `grep -n "token\|davPass" fw-marks.user.js` 自己看一遍

脚本头部 `@connect` 声明的域名就是它被允许联网的**全部范围**：`api.github.com`、
`dav.jianguoyun.com`。除此之外连不出去。

> 所以：如果你想换成别家的 WebDAV（不是坚果云），除了改设置页里的地址，
> 还得在脚本头部加一行 `// @connect 你的域名`，否则扩展会直接拦掉请求。
