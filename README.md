# 废文网 · 书签标记 & 云同步

给[废文网](https://www.xn--pxtr7m5ny.com/)加上它本来没有的**书签、章节标记和阅读进度**，
并且在 iPhone 和 Mac 之间同步。

iOS / macOS Safari 用户脚本。不需要 Xcode，不需要签名，不会过期。

> 改代码的人请看 **[开发笔记 DEVELOPING.md](DEVELOPING.md)** —— 本地测试台、
> 站点真实 DOM 结构、数据结构与同步设计、发版流程都在那里。

## 能做什么

**读的时候，操作都直接摆在网页上** —— 每章标题下面一条，点一下就标，不用进面板：

```
            第十二章 ○○○
   [精彩] [一般] [跳过]  [🔖]  [21/30]
```

| 功能 | 说明 |
|---|---|
| **章节标记** | `精彩` / `一般` / `跳过`，点一下就标、再点取消 |
| **书签** | 标「这一章」，一本书想标几章标几章，点一下就跳回去 |
| **阅读进度** | 在单章页自动记录，目录页顶上一条「▶ 上次读到…点这里继续」，书名旁那条也能点着跳 |
| **书籍标签 / 书评** | 自定义标签（追更中、甜文、弃坑…）+ 整本书的书评，书名后点 ✏️ 随手写 |
| **查新章** | 点一下，脚本自己去数目录，告诉你在读的书更了几章（`第几章/共几章`） |
| **一眼看全** | 书名后面挂标签、目录里每章挂角标、书列表里标出读到哪 |
| **云同步** | GitHub 私有仓库 + 坚果云 WebDAV 双备份，两边都是鉴权存储 |

**没有悬浮球** —— 那玩意儿会实打实压住网站自己的按钮。需要写字和查列表时才进面板。

## 一、装到 iPhone

装好之后更新不用再传文件 —— 脚本是**按链接**装的。

1. App Store 搜 **Userscripts**（作者 quoid，免费开源）→ 安装 → **打开一次 App**
2. 「文件」App → `我的 iPhone` → 新建一个文件夹（叫 `Userscripts` 就行）
   → 回 Userscripts App → `Save Location` → **Change** → 选它
3. iOS 设置 → Safari → 扩展 → **Userscripts** → 打开
4. Safari 打开废文网 → 点地址栏左边的 **ᴀA** → 扩展 → Userscripts → **始终允许**
5. **Safari 里直接打开脚本链接**：
   <https://raw.githubusercontent.com/voltage0045/fw-marks/main/fw-marks.user.js>
   然后**打开 Userscripts 扩展弹窗** → 会冒出安装提示 → 点它装进去
6. 回废文网**刷新**，顶栏（「文库」「收藏」那一排）多出 **📑 我的标记** = 成功

> 三个已知脾气：
> - 弹窗里**没有**「填链接」的入口，装远程脚本只能走第 5 步那个顺序
> - 链接的**路径**必须以 `.user.js` 结尾（不能藏在 `?query` 或 `#hash` 里）
> - **点一次扩展图标、让弹窗完全加载**，脚本才会开始注入

## 二、装到 Mac

Mac App Store 也有 **Userscripts**，和 iOS 是同一个 App，GM 存储、跨域行为都一样。

1. 装好 → Safari → 设置 → 扩展 → 勾上 **Userscripts** → 对废文网设为**始终允许**
2. 点 Userscripts 扩展图标 → 弹窗里 `+` → **New Remote** → 粘脚本链接
3. 代码会被抓到编辑器里，**点右下角的 `Save`** —— 不点就只是「抓下来待确认」，
   不会落盘、网站上也不会生效
4. 刷新废文网页面

> 两台设备也可以共用 iCloud Drive 里同一个文件夹，改一次两边都生效 ——
> 但**前提是两台登的是同一个 Apple ID**。不是的话按上面走链接安装即可，一样不用传文件。

## 三、更新脚本

脚本头里已经配好了远程更新地址：

```
@updateURL    https://raw.githubusercontent.com/voltage0045/fw-marks/main/fw-marks.meta.js
@downloadURL  https://raw.githubusercontent.com/voltage0045/fw-marks/main/fw-marks.user.js
```

扩展**会定期检查**有没有新版，但**查到之后不会悄悄替你换掉**。所以「发了新版、
设备上版本号没变」是正常的，去下面的入口点一下就行：

| 设备 | 怎么拉新版 |
|---|---|
| **iPhone** | 弹窗里的 **☁️⬇**（Available Updates view）→ 点那条 |
| **Mac** | 编辑器右上角 **⟳** 重新抓 → 再点 **`Save`** |

### 怎么看装的是哪个版本

Safari 点 Userscripts 扩展图标 → 点那条脚本 → 编辑器里第 4 行 `@version`。

Mac 上也可以直接看文件：

```bash
grep -m1 "@version" \
  ~/Library/Containers/com.userscripts.macos.Userscripts-Extension/Data/Documents/scripts/*.user.js
```

### 兜底：直接覆盖文件

链接拉不动时（比如网络不通）还可以手动放文件。**Mac**：

```bash
cp ~/fw-marks/fw-marks.user.js \
  ~/Library/Containers/com.userscripts.macos.Userscripts-Extension/Data/Documents/scripts/
```

> 用外部编辑器改完脚本后，**必须先点开扩展弹窗并等它加载完**，注入才会生效。

## 四、配置云同步（双备份）

顶栏 **📑 我的标记** → `⚙️ 设置`。两个都填上才是双备份，只填一个也能用。

每一路都有**独立开关**：不想用就点成「已关闭」—— 它会退出同步，设置里那一段也会
**折叠起来**不占地方。两个都关掉就是纯本地工具，一个请求都不发。

配完点 **🔍 测试连接** 自查：验仓库和 Token、**列出你账号下真实存在的同步文件夹**
（地址里文件夹名写错是头号原因）、真写一个测试文件验权限，并把**服务器自报的原因**
原样显示出来（比如 `AccountExpired` 就是账户过期），不用猜状态码。

### ① GitHub 私有仓库

**手机上不需要 git**，脚本直接调 GitHub 的 HTTP API（`api.github.com`），
不用客户端、不用命令行、一次 commit 都不用手动做。

1. 浏览器打开 github.com → **New repository** → 勾 **Private** → 建好（不用 git）
2. GitHub → Settings → Developer settings → **Fine-grained tokens** → Generate new token
   - Repository access：**Only select repositories** → 选刚建的那个私有仓库
   - Permissions → Repository permissions → **Contents: Read and write**（只给这一个）
3. 生成的 `github_pat_...` 填进「Token」栏
4. 「仓库」栏填 `owner/仓库名`；**文件夹**默认 `fw-marks`（留空＝仓库根目录）；分支留空＝默认分支

> 为什么不用 gist：`public:false` 只是「不被列出」，**拿到链接谁都能看**，不是鉴权存储。
> 而细粒度 PAT 只授权**一个**仓库的 Contents，碰不到你别的仓库。

### ② 坚果云 WebDAV

> **不需要付费**：WebDAV 是免费版就有的功能。免费版限的是**流量**不是功能 ——
> 每月 1GB 上传 / 3GB 下载，WebDAV 请求频率每 30 分钟 600 次。本脚本的数据是
> 几十 KB 的 JSON，离这些额度差得远。

1. 坚果云网页版 → 右上角头像 → 账户信息 → **安全选项**
2. 「第三方应用管理」→ 添加应用 → 名字随便填 → **生成密码**
3. 填进设置页：
   - 账号 = 坚果云注册邮箱
   - 应用密码 = 刚生成的那串（**不是登录密码**）
   - 地址填**文件夹**，结尾带 `/`：`https://dav.jianguoyun.com/dav/我的坚果云/fw-marks/`
     > ⚠️ **子文件夹不存在会自动创建**（脚本会发 MKCOL）。但 `/dav/` 下的
     > **第一层同步文件夹必须已经存在** —— 根目录只是它们的列表，写不进去。

填完点「保存设置」→「立即同步」。两行都显示 ✅ 就成了。

### 同步逻辑

每次同步：**两边都拉下来 → 和本地逐条比 `updatedAt` 取最新 → 合并结果推回两边**。

- 手机标了 A 章、iPad 标了 B 章 → 合并后两边都在，不会互相覆盖
- 哪个云端落后 → 推送时自动补齐
- 一个云端挂了 → 另一个照常工作，设置页会显示 ⚠️ 和失败原因
- 删除是软删除（打 `deleted` 标记），所以删掉的不会被同步「复活」
- **阅读进度只同步到「第几章」**：章内读到百分之几、那句定位原文只留在本机。
  换设备接着读时落在那一章开头；同一章里滚来滚去也就不会每滚一下都往云端推一次
- **Token 和密码只存本机，永远不会上传到任何云端**

默认打开网页时会静默同步一次（距上次超过 5 分钟才触发），失败不弹窗打扰。

> 同步的内部机制（一表一文件、按键名排序、冲突合并与去重）写在
> [DEVELOPING.md](DEVELOPING.md#同步设计) 里。

## 五、用法

> 面板有两个入口：
>
> - 网站**顶栏**多出一项 **📑 我的标记** —— 全站都能进
> - **书籍页目录上方**一排按钮 —— 就近操作

### 书签 vs 阅读进度 —— 两码事

| | 阅读进度 | 书签 |
|---|---|---|
| 怎么来的 | **自动**记，滚动时持续更新 | **手动**加，点 🔖 |
| 记到多细 | 读到**哪一章的哪个位置** | 只记**哪一章** |
| 一本书能有几个 | 只有 1 个 | 想标几章标几章（一章最多一个） |
| 会不会被覆盖 | **会**，一直被最新位置顶掉 | **不会**，只有你自己能删 |
| 要起名字吗 | 不用 | **不用** —— 章节名就够认了 |

所以：想「下次接着读」靠进度就行；想「这一章以后要回来看」就加书签。

**加书签**：正文页每章标题下面那条标记条上点 `🔖`。只有一个图标，没有字：
- **亮的 = 这一章标了**，灰的 = 没标
- **再点一次 = 取消**
- 一章最多一个书签，所以手抖连点也不会攒出一堆重复的

**看/跳书签**：
- 每章标记条上的 🔖 亮着就是标过了
- 目录页章节后面挂 🔖，书名后面和书列表里挂 `🔖n`（标了几章）
- **书籍详情页**站点标签下那一行的 **🔖n** 点开，按章节顺序列出书签在哪几章，点一条就跳过去
- 「📖 标签 / 书评 / 书签」面板里也能看、能删
- 「📑 我的标记」里有书签的书卡片上标 `🔖n`；搜索框旁边的 **🔖** 一点，只看有书签的书
- 书签会连同章节名一起进搜索

跳转用的是章节固定链接 `/posts/{id}`，**不是 `?page=N`** —— 作者一更新页码就漂了，
固定链接才稳。跳过去落在那一章的开头。

### 正文页

- **每章标题下面一条标记条**：`精彩` `一般` `跳过` 三个钮，点一下就标，再点取消；
  旁边 `🔖` 是加书签
- 标记条上那个红色小条是进度（`21/30`）。它**不跳转** —— 点它是清掉这本书的进度，
  会先问一句
- **章末也有一条**：标记、书签，外加一个 **📑 我的标记** 直接呼出面板（不放进度）。
  读完一章人就在末尾，不用滚回章首。最后一章这里还有「✓ 我读完了」
- **只在单章页记进度**（带「上一章 / 目录 / 下一章」的那种页面）。
  「论坛模式」（一页好几章夹着回帖）多半是在翻评论，在那儿滚动不会挪进度
- 点评、回帖的单独页面也不会被当成章节记进度
- 定位优先用**视口顶部那句话**的文本锚点，换字号也能精准找回；
  锚点对不上时退回「那一章 + 章内百分比」

> 同一页里混着的回帖不会被当成章节 —— 回帖没有标题行，脚本据此剔掉。

### 书籍介绍 / 目录页（`/threads/{书}/profile` 和 `/threads/{书}/chapter_index`）

> 目录有**两个入口**：书籍介绍页里嵌的那份，和「目录列表」独立页。两者结构一样，都认。
- 角标（标签、状态小条、标了几章、有书评则 📝）挂在**站点自己那排标签的下一行**，
  不占面包屑和大标题的地方。状态小条**点一下直接跳回去**，旁边还有个**清除进度**
- 纯目录列表页没有那排标签，那儿就**只挂标签不挂进度** ——
  底下那条「上次读到…点这里继续」已经把进度说清楚了
- 这一页是**章节列表的权威来源** —— 章节数、第几章都以它为准。
  只逛目录列表页也会更新：列表页上的新章会**合并**进来（但它漏掉的限阅章节不会因此丢掉）
- **目录上方压一条**「▶ 上次读到「章名」xx% —— 点这里继续」，点了直接跳回去
- 每个章节标题后面挂上你打的标签色块，读到的那章前面有 ▶
  （手机版目录和桌面版表格都画，显示哪个由网站自己的响应式决定）
- 目录上方那排按钮点「📖 标签 / 书评 / 书签」，可以写**整本书的书评**、打**自定义标签**
  （点「＋ 新标签」新建，用过的会进标签池，以后直接点选）

### 书列表 / 搜索结果（`/books`、`/thread_index`、标签页…）
标签这些短东西挂在**书名后面**；**状态小条**贴着一句话简介那一行、**靠最右**
（文库、频道页那一行右边已经有「回响 / 字数」，就紧挨在它左边），
而且用短文案（`▶ 32/105`）—— 不然章节名一长就把简介顶到下一行去。
扫一眼就知道哪本在追、哪本读完了、哪本弃了。**点一下就跳回读到的位置**，
不用先点进书籍主页。

### 我的标记

顶栏 **📑 我的标记**（章末那条上也有）打开就是一张书单，每本书一张卡片：
读到哪（`第几章/共几章`、`▲ 有新章 n`）、标签、书评、标过的章节、有几个书签（`🔖n`）都在上面。
可以「继续读」「去目录」「已读完」「清除进度」「接下来看」。

书单分四组：**在读 → 接下来看 → 读完了 → 弃坑**。点组名能**收起来**（记在这台设备上），
组名**最右边的 🔄 只查这一组有没有新章**。搜索框能搜书名、章节名、书评、标签、书签所在章；
旁边的 **🔖** 一点就只看有书签的书。

面板常态只占屏幕 **2/3**，上面露着一截背景，点背景就关（背景盖在网页上面，
不会点到底下的链接）；也可以点「关闭」。**按住标题栏往上拖 → 全屏，往下拖 → 回常态**，
从常态再往下拖一大截就是关掉。标题「我的标记」后面那个 **⚙️** 直接进设置。

**随手写书评 / 打标签**：书名后面那支 **✏️** —— 点开就是标签格子 + 书评框，
**点「写好了」才算数**；没点就关掉（关面板、点别的书的铅笔），这次改的都不存，
会提示一句。所以在编辑框里点了「弃坑」，卡片也不会当场跑去弃坑组。
清空书评 / 标签 / 章节标记的按钮也在这个编辑框里。

**接下来看**：想读还没开读（或者先放一放）的书，排进这一组。入口：
- 书籍详情页、站点标签下面那一行的 **📌 接下来看**（还没读过的书主要从这儿排）
- 「📖 这本书」面板里，以及书单里在读那些书的卡片上

先排进来的排在前面。**一打开它的单章页开始读，就自动挪回在读**。查新章不查这一组。

**查新章**：站内那个「有更新」标记不太准，所以章节数是脚本**自己去数目录**得出的
（以**书籍详情页**那份为准 —— 目录列表页会漏掉「单章限制阅读」这种章节）。
这件事**只在你点的时候才做**（分组标题右边的 🔄），不后台偷跑；
点哪组查哪组，站点标了完结的书跳过。
刷新不会打乱列表顺序：在读按**最近在读**排，跟「查过没查过」无关。

**标已读完**：两种方式，进度都照样存着不受影响 ——

- 书单里每本书有个 **已读完**（再点一下就挪回在读）
- 读到**最后一章**时，**正文末尾**那条标记条上会多出 **✓ 我读完了**
  （读完那一刻人就在末尾）。点它顺手把进度补成 100%，再跳回书籍主页

另外，**完结文翻到最后一章就算读完**，不要求那一章也滚到 100%。

**打了「弃坑」标签**的书自动归到最后一组；读完的和弃坑的都不显示 `第几章/共几章`
（都收尾了，盯着章节数没意义），刷新时也不去查它们。

**改标签**：打错字了点标签格子里的 **✎ 管理** —— 改名和删除都会**同时改掉所有书**
身上那一份，不会只改一半。

### 状态小条：一个位置说清三件事

网页上（书籍主页、书列表、面板里的书名后）都有同一个小条，三种状态共用一个位置：

| | 什么时候 |
|---|---|
| `✕ 弃坑` | 打了「弃坑」标签**且有进度**（没读过的书标弃坑，那就只是个普通标签） |
| `✓ 已读完` | 你按过「已读完」，或者完结文已翻到最后一章 |
| `▶ …` | 在读。地方宽的时候显示章节名，窄的时候显示 `32/105` |

弃坑优先于读完 —— 坑都弃了，读到第几章无所谓了。
面板里不另挂 `✕ 弃坑`：卡片上本来就挂着「弃坑」这个标签，再标一次就是同一件事说两遍。

**正文页**的那条例外：它不跳转（人就在书里读着，跳「读到的位置」等于原地打转），
**点它是清掉这本书的进度**，会先问一句。

### 黑夜模式

**📑 我的标记** 右上角的 🌙 一点就切，`⚙️ 设置` 里也有开关。网页和面板一起变暗；
作者在正文里自己上的颜色、还有脚本画的那些彩色小条都原样保留。
只记在当前设备上（手机和 Mac 各自定），开着时打开新页面不会先白闪一下。

**三种数据互相独立**：清进度不动书签和书评，清书评不动进度和书签。
设置页底下有「复制导出 JSON」和「粘贴导入」做本地兜底备份。

|---|---|
| 目录页角标位置不对 / 没出现 | 顶栏「📑 我的标记」→ `⚙️ 设置` → **重新校准** → 点一下任意章节链接 |

| 点「上次读到」只是刷新了页面 | v1.0 的老毛病，v1.2.1 已修。首次打开会自动清掉那条假记录并提示，重新读一次就会记对 |

## 七、数据存在哪

- 本地：Safari 扩展存储（不是网站的 localStorage，Safari 的隐私清理不会碰它）
- 云端：GitHub **私有仓库** + 坚果云 WebDAV，**两边都是账号鉴权**，各一份完整 JSON
- 手动：设置页可随时复制导出 JSON

数据结构（同步的就是这几坨）：

| | 内容 |
|---|---|
| `books[书id]` | 书名、自定义标签、书评、章节总数/完结状态 |
| `prog[书id]` | 阅读进度：读到哪章（同步）、章内位置和定位锚文本（只留本机） |
| `chaps[书id\|章id]` | 章节标记（精彩/一般/跳过） |
| `bmks[书id\|章id-时间戳]` | 书签：哪一章 + 章节名 |
| `tagPool` | 用过的自定义标签，下次直接点选 |

> 老数据会自动迁移，不用手动处理。结构演变的原委见
> [DEVELOPING.md](DEVELOPING.md#数据结构)。

### 账号凭据说明

**脚本里没有任何账号信息**，一行都没有。搜 `token` / `davUser` 你会看到它们的初始值全是空字符串。

- 云同步**完全可选**。不填任何东西，脚本就是个纯本地工具，不联网、不发请求
- 想同步的话，凭据是**你自己在「⚙️ 设置」里粘贴进去的**，不会跳转登录、
  不会走 OAuth、也不会有人代你登录
- 建议用的都是**受限凭据**，不是你的登录密码：
  - GitHub：**细粒度** PAT，只授权**那一个私有仓库**的 Contents 读写，碰不到你其他仓库
  - 坚果云：**应用密码**（第三方应用管理里单独生成的），可以随时单独吊销
- 凭据存在扩展本地存储里，**只在向 `api.github.com` / `dav.jianguoyun.com`
  发同步请求时用作认证头**。它们不会被写进同步的 JSON，所以云端那份备份里也没有凭据

脚本头部 `@connect` 声明的域名就是它被允许联网的**全部范围**：`api.github.com`、
`dav.jianguoyun.com`。除此之外连不出去。

> 所以：如果你想换成别家的 WebDAV（不是坚果云），除了改设置页里的地址，
> 还得在脚本头部加一行 `// @connect 你的域名`，否则扩展会直接拦掉请求。
